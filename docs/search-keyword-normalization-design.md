# 搜索关键词规范化设计

## 目标

在商品搜索页提交搜索前统一清理关键词首尾空格，阻止纯空白搜索，并让搜索历史和路由查询始终保存规范化后的词。

## 范围

只修改 `frontend/src/views/shop/search/index.vue` 的本地搜索交互，不改后端 API、数据库、路由结构、全局 Pinia 状态或搜索结果接口参数名称。

## 行为

- 用户提交 `" 手机 "` 时，页面以 `"手机"` 作为关键词更新查询、调用现有搜索结果 API 并保存搜索历史。
- 用户提交空字符串或仅由空白字符组成的文本时，页面显示 Element Plus 警告“请输入搜索关键词”，不更新路由、不增加历史、不请求结果或建议接口。
- 搜索建议请求仅接收规范化后的非空关键词；清空输入继续保持现有的清空建议行为。
- 历史标签、热门词和建议项触发搜索时也经过同一个规范化入口，避免带空格的重复历史记录。

## 实现

在组件脚本中创建一个纯函数 `normalizeKeyword(value)`，返回 `String(value ?? "").trim()`。`handleSearch` 先调用该函数，空值时调用 `ElMessage.warning` 并返回；非空时把 `keyword.value` 更新为规范化值，然后执行现有的关闭建议、记录历史和更新查询操作。输入防抖回调在调用 `getSearchSuggestions` 前同样使用规范化值。

## 验证

- 手工验证普通词、首尾空格词和纯空白词的三种提交结果。
- 运行 `npm run build` 确认 Vue/Vite 编译通过。
- 运行 `npx eslint src/views/shop/search/index.vue`；如果现有 ESLint 配置对该文件有历史问题，报告该问题，不在本变更中做无关格式化。

## LORE 验证价值

该 PR 会同时包含输入规范化、用户反馈、异步建议调用边界与历史记录一致性，足以让 LORE 对一个低风险真实前端行为改动生成审查意见，同时不影响订单、支付或数据模型。
